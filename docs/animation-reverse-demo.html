Reversible apple animation

The table keeps its state. Press the buttons in any order.

Why this reverses cleanly. The table is state, not a picture an animation paints. level holds how many apples are on it, and each apple has a CSS transition between hidden and shown. A transition animates whatever changed, in whichever direction it changed — so the same rule handles filling and clearing, and the animation always begins from what is already on screen. Nothing appears from nowhere. Scaling down from a table that already has ten apples simply removes them, in the reverse order, ending on the one apple that was always there.
